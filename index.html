    How do I start and stop the application?

    Install Node.js 22 or newer, open a terminal in this application’s folder, and run:

    npm start

    Open http://127.0.0.1:4317. Stop the server with Ctrl+C in that terminal. You do not need npm install: there are no runtime dependencies.

    If port 4317 is busy, stop your previous instance or run PORT=4320 npm start and open port 4320. For a fresh isolated profile, run SKILLS_VIEWER_DATA_DIR=/absolute/path/to/profile npm start.

    From a private GitHub repository: clone its URL with git clone, enter the cloned folder with cd, then run npm start. Private clones require an authorized GitHub account or SSH key.

    What are a skill, library, agent, and workspace?
    Skill
    A directory with a regular file named SKILL.md containing agent instructions. It may also contain scripts, references, or assets. This app never executes those scripts.
    Library
    The combined view of skills found in registered agent and workspace folders. It is an inventory, not another storage directory. Links to the same real directory appear once; independent copies appear as separate entries.
    Agent
    A named destination, such as Claude Code or Sahaa, with a configured skills folder. The agent itself decides whether and how to load SKILL.md.
    Workspace
    A repository or local project directory, such as logs_fw. Registering one lets the dashboard inspect known skill subfolders. You can also register a folder directly containing skill directories.
    System level
    In this app, your user-level agent folders under your home directory. This is not an operating-system-wide installation for every user.
    Shared library
    The destination ~/.agents/skills. Some agents read this convention, but it does not automatically make skills accessible to every agent.
    What does each page do?
    Library
    Search and filter the inventory by scope or source. Select a skill to inspect its real folder, raw instructions, supporting filenames, and known locations. Share it, edit its source SKILL.md, or remove one chosen location.
    Agents
    See the built-in agent presets and custom destinations. Folder evidence explains why an entry is counted. Configure a skills path or add a new agent. Removing a custom registration forgets it without deleting files.
    Workspaces
    Register a repository or skills folder. Discover folders suggests other repositories in common project directories; you choose which to register. Removing a registration does not delete the repository or its skills.
    Activity
    See the last 200 sharing, removal, and restoration events. Disconnect an unchanged link created by this app, or restore a removed skill location. Pending recovery records are kept independently of the 200-event limit.
    Help & FAQ
    Learn the terminology, folder conventions, startup steps, limits, and safety rules. The information icons around the app open the relevant answer here.
    What is “Link to source”? How is it different from copying?

    A link is a filesystem symbolic link: a directory entry at the destination that points to the original skill directory. It is not a copy, upload, periodic sync job, or internet shortcut.

    Original directory:
~/projects/logs_fw/.github/skills/log-triage/
  SKILL.md
  scripts/

Agent destination:
~/.copilot/skills/log-triage
  points to the original directory above

    The destination sees the original SKILL.md and supporting files. Editing through either path edits the same underlying files. There is no second version to keep synchronized. The source must remain available, and the receiving agent must support directory symlinks and that skills path.

    An independent copy duplicates the directory. It can be edited separately and survives removal of the source, but later changes do not propagate. Copies containing symbolic links or special files are refused; the limit is 25 MiB and 2,000 files/folders.

    Existing destinations are never overwritten or merged. A destination that already uses the same source is unchanged; another skill with the same folder name produces a conflict.

    How do I reuse logs_fw skills in Sahaa or another agent?
    1. Register the logs_fw repository in Workspaces.
    2. In Agents, configure Sahaa with the exact folder its documentation says it loads. There is no verified Sahaa skills-folder default in this application.
    3. Select the workspace skill in Library and choose Share with agents.
    4. Select Link to source and the destination. Select other configured agents or Shared library too, if wanted.
    5. Start a new agent session or use the agent’s reload command if it caches skills.

    If Sahaa or Zllm does not support skills, creating a folder or link cannot add that capability. Use an agent-supported instruction mechanism instead. This dashboard does not inject instructions into agent conversations.

    What does Rescan do? Does it change my files?

    Rescan re-reads configured agent folders and registered workspace skill locations, checks known agent paths, parses SKILL.md names/descriptions, and resolves symlinks to group the same source. It refreshes counts and reports missing, broken, or unreadable locations. It does not copy, link, install, execute, or delete anything.

    The app also reads the inventory on page load and after changes. There is no timer, filesystem watcher, or background sync. Click Rescan after an external edit. Searches and filters only select from the loaded inventory; selecting a skill reads its detail again.

    Inventory scanning is limited to 6,000 candidate folders. Documents larger than 512 KiB are not previewed or edited. Only name/description metadata is parsed, not all YAML syntax; the original Markdown is displayed as escaped text.

    Why are Sahaa and Zllm listed? What intelligence detects an agent?

    There is no AI, executable lookup, package inspection, process inspection, or automatic capability detection. Sahaa and Zllm were included as built-in presets because they were named in the original app requirements.

    For built-in Sahaa, the app checks whether ~/.sahaa exists. For Zllm, it checks ~/.zllm. Other presets check their known top-level directory, such as ~/.claude or ~/.codex. The Agents page shows the exact checked path and whether it exists.

    “Known agent paths” counts existing preset/custom paths, excluding Shared library. A leftover directory can count even if the agent was uninstalled. This is folder evidence, not proof that an agent is installed, running, or able to load skills.

    Sahaa and Zllm have no default skills destination here. “Needs skills folder” means you must configure one; finding their top-level directory does not establish skill support. Once you configure an agent, its evidence path becomes the configured skills folder.

    How is a new agent discovered or added?

    Unknown agents are not discovered automatically. Installing a new CLI or adding ~/.new-agent will not create a dashboard entry.

    Use Agents, Add agent, enter its name and documented absolute skills path. The path can be missing initially; it is created only when you share a skill. Rescan then checks that registered path and reads any skill directories in it. The shared-library convention alone is not a guarantee of compatibility.

    To support automatic discovery of another named agent in the future, a developer would add its documented preset to BUILT_INS in core.mjs. Generic custom registration needs no code change.

    Which folders are scanned? What should a skill folder look like?

    The ~ symbol means your home folder. Names beginning with a dot are normally hidden folders on macOS and Linux. A workspace path belongs to your project, not to this dashboard’s installation folder.

    Default user-level locations are ~/.agents/skills, ~/.claude/skills, ~/.codex/skills, ~/.copilot/skills, ~/.cursor/skills, and ~/.gemini/skills. They can be configured in Agents.

    For each registered workspace, the app checks .agents/skills, .github/skills, .claude/skills, .codex/skills, .copilot/skills, .cursor/skills, and .gemini/skills. It also checks the registered folder itself for direct skill directories.

    logs_fw/
  .github/
    skills/
      log-triage/
        SKILL.md
        scripts/       (optional)
        references/    (optional)

    A standalone Markdown file or a directory without SKILL.md is not a skill in this app. Plugin caches and vendor-specific formats are not crawled automatically; register a compatible plugin skills folder explicitly.

    How is Discover folders different from Rescan?

    Discover folders looks for unregistered repositories containing known workspace skill paths. It searches the current project’s parent plus ~/Projects, ~/AI Projects, ~/Developer, ~/code, ~/repos, ~/work, and ~/git.

    It goes at most three levels deep, stops descending once it finds a skill location, caps the search at 1,500 directories, and skips hidden/dependency/build directories. It suggests candidates without registering them. It does not search the entire disk, open arbitrary agent configuration files, or discover new agent brands.

    Use Add workspace for other paths, deeper repositories, or a directly managed skill collection. Permission errors are shown rather than silently treated as success.

    How do I remove a skill? Can I undo it?

    Select the skill in Library, choose Remove skill, select the exact location, and type the skill name to confirm. A linked location removes only that link; an original or independent copy moves the whole directory into local recovery storage.

    The source cannot be removed while other registered locations use it. Remove those links first. Links outside registered folders cannot be detected, so check other consumers before removing a source.

    Use Activity, Removed skills, Restore to put a location back. Restoring refuses an occupied original path. Recovery is kept under your profile’s trash folder without automatic expiry; this is application recovery storage, not the operating system’s Trash.

    Removal uses an atomic move on the same filesystem. If the skill is on another filesystem, removal is refused without copying or deleting it. A profile located on the skill’s filesystem can be used instead. No permanent-delete button is provided.

    Removing an agent/workspace registration only hides that registration; it does not remove its skills. Disconnect link in Activity only unlinks an unchanged link previously created by this app.

    Where are settings, history, and removed files stored?
    ~/.config/skills-viewer/
  settings.json       Agent/workspace registry and history
  trash/
    <removal-id>/
      skill           Archived directory or symbolic link

    SKILLS_VIEWER_DATA_DIR overrides the entire profile location. Settings are written atomically after changes, not on a read-only scan. The latest 200 activity events are retained; pending recovery records are not expired when old history is trimmed. Recovery folders are not a backup system: keep important original skills in version control.

    The app has the permissions of the user who starts it. Access-denied errors are shown. Do not run it as root or expose it through a network proxy. There is no cross-process lock, so run one server per profile and avoid simultaneous external writes during edits, removal, or restore.

    Is anything sent to GitHub or the cloud? Must the dashboard stay open?

    The running application makes no external network requests. Publishing this application’s source to GitHub does not upload your registered skill folders, local profile, or recovery files. GitHub authentication is needed only for repository access, not for running the dashboard.

    Links and copies remain usable with the browser and server closed. A linked source must stay available. Agent caching and skill compatibility are controlled by each agent. The footer shows server process RSS only, not the browser’s memory usage.

    Why is a skill missing, duplicated, or not loading in an agent?

    For missing skills: check the registered path and supported folder structure, verify SKILL.md is a regular readable file, look at scan warnings, and click Rescan. A symlinked SKILL.md itself is refused, although linking the whole skill directory is supported.

    Separate copies appear separately even when their names match. Directory symlinks to the same real source are grouped into one library entry. An agent’s count measures locations in its own folder, not additional unique content.

    For agent loading: verify the actual agent/version supports skills and directory symlinks, configure the folder it really reads, check that the source still exists, and restart/reload that agent. Folder evidence never proves loading works.

    If an edit is rejected as stale, copy your draft somewhere safe, cancel the edit, rescan, and reopen the skill before trying again. If recovery storage or an original path changed, the app refuses to overwrite it; inspect the reported paths manually.
